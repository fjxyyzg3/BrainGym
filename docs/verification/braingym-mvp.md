## 验证方法与边界

规则与时序先以接口桩运行，9 项断言因行为缺失失败，随后同一测试通过。服务端先以 501 响应运行，6 个 API 场景失败，实现后通过；CLI 和后续分页/精度用例为真实组件回归覆盖，没有伪造 RED。

浏览器时钟用于推进固定节奏的完整对局；网络路由只模拟上传失败和响应丢失，服务端与数据库仍是真实实现。Playwright 会强制页面保持可见，所以切后台场景单独启动无焦点覆盖的 Chromium，通过原始 CDP 创建并激活另一标签页；没有修改 `document.hidden` 或伪造事件。已验证登录对局的原生 hidden 事件、中断界面和零上传。

移动端使用触屏设备模拟与真实浏览器 tap，尚未覆盖实体 iOS/Android 的锁屏流程或 Safari。当前验收证明了页面可见性事件的处理，不能替代所有设备的实机兼容性测试。

按产品约定，服务端只验证汇总，不证明真实游玩或客户端时钟可信；完成时间不用于鉴权或计分。
