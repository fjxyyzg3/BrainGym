> 摘要：正序／倒序 Corsi 方块的出题、展示、整题复现、长度成绩、自适应起点、进度恢复与数据合同。

# Corsi 方块顺序记忆

大厅提供一张“顺序记忆 · Corsi 方块”卡片。`#corsi` 进入正序，`#corsi-backward` 进入倒序；两方向分别记录起点、历史和最佳，规则版本均为 `1`。九格按从左到右、从上到下编号 1～9，可用鼠标、触屏或数字键作答。

## 出题与复现

首次从 2 格开始。每级固定两题，至少一题正确便增加 1 格，两题都错结束整局；第一题正确后仍需完成第二题。序列长度不设固定玩法上限，超过九格时允许再次经过已有格子。首格从九格等概率选取，后续每格从上一格之外的八格等概率选取，允许隔位重复。同级两题的序列不同。

每步亮起 500 ms、留空 500 ms；最后一步也完整留空后才开放复现。正序沿展示顺序作答，倒序从最后一步开始。复现不限时，只显示已输入数量和按下反馈，不显示逐步正误或已输入序列，也不能撤回。输入满本题长度后整体判定；**记不住了**将本题计为失败。题间显示文字反馈，点击**下一题**才开始后续展示，不回放答案。

未完成局在主动结束、离开、切换方向、切后台或锁屏时作废，题间等待也包括在内。已完成结果不因后续后台事件撤销。

## 成绩与下局起点

成绩为本局至少一题正确的最高长度，单位为“格”。首级两题都错时，内部成绩为 0，界面显示“未通过起始 X 格”；完整失败局可留在历史中，不参与最佳。两方向分别选一项最高通过长度最佳，同成绩先取首次入库较早的记录，再按结果 ID 升序稳定选择。

下局起点由同方向上一局推导：

| 上一局表现     | 下局起点                                             |
| -------------- | ---------------------------------------------------- |
| 开局第一题失败 | 本局起始长度减 1，最低为 2；后续成功不改变此优先规则 |
| 开局第一题正确 | 本局每级第一题就答对的最高长度                       |

账号起点只采用服务端已保存、时间有效且属于当前进度世代的完整局。最近一局按完成时间、首次入库时间、结果 ID 依次倒序确定；迟到旧局增加历史，不覆盖较新的进度。本局建议起点与账号当前起点分别显示，保存失败不更新服务端进度。

游客的两个起点只保存在当前文档的内存中，切换方向可复用，刷新或新开页面后都回到 2 格。游客没有私人历史或最佳，结果与起点不在登录或恢复联网后补传。

## 进度恢复与异常处理

准备页的**从 2 格重新开始**只恢复所选方向，保留历史和最佳。账号恢复通过递增 `progressEpoch` 切换进度世代，刷新、换设备后生效；旧世代已开局或未上传的完整结果仍可保存历史和参与最佳，但不决定新起点。游客恢复只修改本页面内存。

确认恢复时固定预期用户与世代。身份或世代变化返回 409；恢复响应丢失后先重新读取进度，不盲目重复 POST。正常开局始终重新读取身份、起点和世代；校验失败或离线时，需明确选择游客练习。

序列按需生成，每批至多处理 256 步，批次之间交还事件循环，取消会使旧任务失效。资源预算不足、分配失败或数值无法安全表示时整局作废，不截短序列、不计成绩、不自动降低起点；可返回准备页恢复到 2 格。运行资源检查不构成固定玩法长度上限。

展示使用单调时钟，每个亮／空相位都需要视图提交回执。漏交付、跨过相位，或相位／复现边界提交延迟超过 100 ms 时整局作废；恰为 100 ms 仍在容差内。最后留空未提交时不能进入复现。该机制确认 DOM 提交，不能证明屏幕像素实际呈现。

## 摘要、时间与存储

`CorsiGame` 独立于 `NBackGame`。共享规则校验四项常量规模摘要：`startLength`、`failedLength`、`firstTrialCorrect`、`maxFirstTryLength`，服务端据此复算成绩与建议起点；不上传题目、逐步输入或逐级日志。长度及派生值须为安全整数，请求体上限仍为 8192 字节。

正常开局的 `GET /api/corsi/progress` 返回会话用户、服务端 `serverNow`、两个方向的起点、世代和最佳。客户端在收到响应时记录 `performance.now()`，完整结束时间取服务端锚点加单调经过时间，游玩中修改设备日期不影响它。新结果的完成时间最多可比首次入库时间晚 5000 ms，超出该容差 1 ms 就拒绝；过去时间不因延迟上传拒绝。先查幂等，再对新结果判时，重试沿用原 ID、完成时间与首次入库时间。

既有异常未来记录按不可变的首次入库时间判定，永久排除在起点推导之外，历史标记异常，最佳仍保留其长度表现。当前日期后来越过该完成时间也不会使它重新决定起点。

`corsi_results` 保存成绩摘要，`corsi_progress_resets` 保存用户／方向／版本的当前世代与最后恢复时间。两表以附加扩展方式在同一事务中初始化，支持重复打开，核心 `PRAGMA user_version` 保持 `1`；不修改既有 `results` 表、N-back payload 或历史分数。当前程序在两张成绩表之间统一检查同用户结果 ID，规范化内容相同返回原记录，不同内容返回 409。

历史和最佳复用 `history`、`bests` 的 `game=corsi-forward`／`corsi-backward` 参数；历史每页 20 条，最佳排除 0 格。`POST /api/corsi/progress/reset` 接受 `game`、`expectedUserId`、`expectedEpoch`，会话决定实际用户，预期用户只作前置校验，事务中比较并递增世代。所有私人接口沿用有效 Cookie 会话、Origin 校验、`no-store` 和基础路径合同。
